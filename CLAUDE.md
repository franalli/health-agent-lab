# CLAUDE.md

Operating manual for Claude Code in this repository. `architecture.md` is the source of truth for *why*; this file is the *how*. Read both before changing anything.

## What this is

A **Health Intelligence Service**: a persistent assistant over a member's longitudinal lab history that (1) answers free-form health questions grounded in their own results and (2) proactively surfaces trajectory drift, refusing or escalating to a clinician when warranted. Synthetic data only.

## The one law

**The LLM is a language layer over a deterministic core — never the core itself.** Every number, range comparison, trend verdict, and escalation decision is computed in pure Python (`analysis.py`, `safety.py`). The LLM only renders that ground truth into careful prose and routes open-ended phrasing. It must never compute a statistic, decide an escalation, or assert a value the deterministic layer did not produce.

If a change would let the model decide something safety-relevant, it is wrong. Stop.

## Hard invariants — do not break

- **`analysis.py` is pure.** No DB, no LLM, no network, no clock — typed inputs in, a typed `TrajectoryAnalysis` out. This is what makes statistical correctness unit-testable. Keep it that way forever.
- **The deterministic floor is always on.** `safety.py` computes an escalation floor from the analysis; the validator enforces `response.escalation >= floor` on *every* turn, both modes. A softer-toned answer can never sit on a harder floor.
- **Escalation ≠ out-of-range.** A value merely outside its reference range is at most a `notable` observation. Escalation (`clinician_review` / `urgent`) is reserved for panic thresholds and RCV+FDR-significant adverse trajectories — **or, where the series is too short for FDR (`3 ≤ n < n_min`), an adverse change that clears RCV *and* is strictly monotonic** (the sub-`n_min` rule; below `n_min` the exact Mann–Kendall p floors at 0.33, so FDR is structurally unreachable and monotonicity is the deterministic stand-in for the significance test — `analysis._sparse_adverse`; `urgent` stays panic-only). A managed condition's expected-high marker must not escalate.
- **Never fabricate.** A marker absent from `trajectory_analysis` — no reading, OR dropped by a `suppress_marker` override (the composer can't tell the two apart) — is answered "not in your current results", never an invented value AND never a value/status/trend *inferred* from related markers, general medical knowledge, or the conversation history (`llm.BASE_COMPOSE_SYSTEM` rule 3, strengthened after the composer confabulated a suppressed well-known marker's status from the surrounding context; a general name mapping onto present markers — "cholesterol"→`LDL`/`HDL`/`Total cholesterol` — is answered from those). Every claim traces to `findings[].evidence[]`. The eval's absent-marker never-event guards a fabricated *number*; the *status* case is covered by a real-composer multi-run, not the harness.
- **Every narrator surfaces the core flags.** A rendered answer — template (`templates.py`) *or* LLM (`compose()`) — must state a marker's panic / out-of-range status, not merely its trend. Trend-only narration of a flagged value falsely reassures. The escalation floor guards the *level*; this guards the *prose*. It passes every structural test — it is caught only by reading the words, so read them.
- **Observation narration is audience-split.** An `Observation` carries two deterministic narrations from one `_classify` signal: `trigger_reason` (the statistical basis — Mann–Kendall *p*, RCV) is **clinician/operator-only** (the raw-JSON readouts), and `member_explanation` is the **member-facing** plain-language text — it states the reference range for an out-of-range value and *never* a test statistic. The member panel renders `member_explanation`, never `trigger_reason`. Both are deterministic for a reason: the LLM is forbidden to print numeric bounds (`llm.py` rule 1 — "the system prints the exact bounds as evidence"), so only this layer may state the real range. The member's referral nudge is **severity-gated** — a bare out-of-range value is `notable`, not an escalation, so it gets no "see a doctor" (mirrors *Escalation ≠ out-of-range*). Lives in `templates.observation_member_explanation` and is **derived at read, not stored**: the `observations` table persists only `trigger_reason`; `member_explanation` is re-composed from the live analysis by the `/observations` projection (`pipeline.observations`, the read-time-derive peer of `trajectory`/`suggestions`), so there is no stored copy to migrate or go stale and it always agrees with the value+range the Trajectory tab shows. Covered by the no-stats-leak + core-flag tests in `test_pipeline.py`. The Mode-2 composer's half of this discipline is **`BASE_COMPOSE_SYSTEM` rule 10** — active observations are *context, not a checklist*: the composer references another observation only when directly relevant to the asked question and never enumerates the list, since the member's proactive findings are surfaced to them separately (the composer prompt is v0's ten hard rules; rules 1 and 5 are the two the `/learn` input-judge screens a corrected answer against).
- **One normalization path.** All input enters through `preprocessing/ingest.py` (the firewall): it parses the supplied bundle's five reference-range shapes, folds vitals in as markers, and writes the internal domain model. Nothing downstream re-parses raw input — including an uploaded `.zip` (the firewall owns zip extraction + the zip-slip guard for `POST /members/upload`). An upload **must** be a `.zip` carrying exactly one `.json` (members), one `.jsonl` (eval set), and one `.csv` (lab panels), discovered **by extension** — a hold-out ships stable extensions, only the base names differ. The firewall **format-gates the first record of each file** against its schema (`MemberBundle` / `EvalCaseInput` / the CSV header+row) and rejects a bad first row / missing-or-duplicated role with a **422 carrying `{error, failures:[{file,row,field,detail}]}`** — every problem reported at file+row granularity, before any side effect. Past the gate, ingest is **lenient: a buggy *later* member row is skipped, not fatal** (`ingest_members` returns a `skipped` list; one malformed bundle never aborts a good batch) — *unless every* member row skips, which ingests nobody: `POST /members/upload` then 422s (rolling back the reserved folder) rather than persisting an empty dataset, and the seed path logs the skips loudly rather than booting a silent partial. Each file is then written to the new dataset folder under its **canonical** name, so every downstream reader stays name-based. *Which* bundle it reads, and *where* new ones are written, is resolved by `preprocessing/datasets.py` — the active bundle from the `DATASET` env var (default `training_data`); the datasets **root** from `HEALTH_DATA_ROOT` (default `backend/data/`, resolved **per-call**). Each dataset is its own sub-folder of the root, so new bundles ingest incrementally, and `POST /members/upload` *creates* such a sub-folder at runtime (uploads are **additive** — never a reseed); the derived `health.db` sits at the root, not inside a bundle.
- **One DB module.** Only `db.py` touches SQLite. Clinical constants and thresholds live in `config.py` (versioned); `.env` is secrets + runtime only.
- **All provider calls behind `llm.py`** — `compose()`, the gate classifier, and the feedback input-judge (`learn.judge_corrected_answer`, the Haiku classifier that screens a corrected answer before it becomes a few-shot exemplar). These three are the only network seams. The judge is a **quality** filter, not the safety boundary (the always-on validator is), so an LLM classifier is the right tool there — see the "learns too literally" note below.
- **Two layers, not one.** The SQLite schema (`schema.sql`) and the Pydantic models (`models.py`) are deliberately separate — do not fuse them into ORM-as-model. The row↔model mapping lives in `db.py`.

## Commands

Dependencies and the virtualenv are managed with **uv**. All commands run from `backend/` (where `pyproject.toml` lives — there is no root workspace).

```
uv sync          # install
make hooks       # install the git pre-commit hook (run once after clone)
make init-db     # create the SQLite schema
make seed        # ingest the supplied bundle
make run         # init + seed + serve API and UI on :8000 (dev; --reload)
make serve       # production-mode serve (no reload; binds $PORT or 8000) — the Render start command
make eval        # run the evaluation harness → report (incl. the feedback-judge accuracy gate)
make eval-judge  # feedback input-judge accuracy gate alone (real Haiku; no key → SKIP)
make lint        # ruff lint+format + gitleaks secret scan over the whole tree
make test        # unit tests
```

> The Makefile is wired as of Phase 3a (`backend/Makefile`); `make help` lists the targets. `make eval` runs the harness (Phase 5a: deterministic scorers → markdown/JSON report in `eval/reports/`); Mode 2 needs `ANTHROPIC_API_KEY` (the report measures real-API consistency and latency/cost). `make eval` also runs the **feedback input-judge accuracy gate** (`eval/judge_eval.py`, a labeled battery through the real `learn.judge_corrected_answer` Haiku classifier — measured, not unit-testable, since the judge is an LLM; a miss — or, with a key present, a transient provider failure that would otherwise skip the gate silently — fails the run alongside a safety never-event); `make eval-judge` runs that gate alone. Both SKIP (never fail) only when the key is *absent*. The UI (`frontend/index.html`) ships as of Phase 6, so `make run` serves the API **and** the static page same-origin on `:8000` (the mount is still guarded — skipped if the directory is absent). The page's Mode-2 chat needs `ANTHROPIC_API_KEY` for the real LLM path; without it, `/ask` degrades to the deterministic fallback (a documented safety behavior, never a 500).
>
> **Pre-commit hooks.** `.pre-commit-config.yaml` sits at the **repo root** (not `backend/`) because it gates the whole tree; the runner and `ruff` are dev deps in `backend/pyproject.toml`, and ruff's config is `[tool.ruff]` there. The gate is two checks — ruff (lint + format) and gitleaks (secrets) — plus basic hygiene hooks. `make hooks` installs it; `make lint` runs it on demand. Bump pinned hook revs with `pre-commit autoupdate`. `E501` (line width) is intentionally not enforced — this repo's long documented comments are by design; the formatter still wraps code.
>
> **Deploy (Phase 8).** `render.yaml` at the **repo root** is the Render Blueprint — one `web` service, `uv sync` build, `uvicorn api:app` on `$PORT`, `/health` check. The lifespan runs `init_db` **+ seed-if-empty** on startup (the build can't see the runtime FS), so a fresh instance self-heals its schema and the 15 members. Shipped **free/ephemeral** (no disk; DB re-seeds on cold start; `POST /members` uploads + `feedback` don't persist); the durable paid-disk upgrade (`/data`, `HEALTH_DB_PATH`) is a commented block in `render.yaml` (§15). `ANTHROPIC_API_KEY` is a dashboard secret (`sync: false`), never committed. The DB path env var the code reads is `HEALTH_DB_PATH` (unset → `backend/data/health.db`).

## How to work here

- **Build in phase order.** `architecture.md`'s build sequence (Phases 0–8) is dependency-ordered; each phase leaves something runnable. Deterministic-first — the whole non-LLM system and every safety decision are built and tested before the LLM goes on top.
- **Keep the schema lean.** Do not add a column without data or a behavior that needs it. Phantom fields are cut on sight.
- **Verify the data contract on touch.** If you change `schema.sql` or `models.py`, re-check the three stay aligned — schema columns ↔ Pydantic fields ↔ the actual data — and that no phantom column crept in. The consistency checks exist for exactly this. After implementing, also reconcile any resulting schema or Pydantic-model drift in `docs/` (e.g. `docs/architecture.md`) so the documented contract matches the code.
- **Routes stay thin.** Every API route is a thin adapter over the `health_intelligence` library; logic lives in the library, not the route. `pipeline.py` is the orchestration seam where that logic lives — `scan` (proactive Mode 1), `suggestions` (reactive Mode 1), and the `ask`/`compose` path (Mode 2) each sequence load → analyze → narrate → persist, and **each runs `safety.validate` against the floor**: this is *where* the "deterministic floor is always on, both modes" invariant is enforced.
- **`/ask` is multi-turn, composer-side only.** `AskRequest.history` carries the prior `(user, assistant)` turns the client replays (there is no server conversation store); `pipeline.ask` caps them to `MAX_HISTORY_TURNS=20` (last 10 exchanges) and threads them into the composer's `<conversation_history>` **only**. The **gate stays per-message** (safety is classified per current message so the floor can only *rise*, never inherit a diluted route from history — documented gap: a crisis stated only in a *prior* turn isn't re-detected on a benign follow-up), and history **never** enters `analyze` or the floor (the one law). Untrusted (client-authored) — composer rule 5 frames it as info-not-instructions, and any marker it names is still re-grounded against the live analysis. Not a context bug: the marker-list "follow-up" answer is the deterministic `_grounded_fallback` after `compose()` threw (`model_version=='deterministic'`).
- **The composer output is repaired at the provider seam, not trusted raw.** Sonnet 5 (forced tool + thinking-disabled — the composer's required config, since forced-tool 400s with thinking-on) intermittently emits its WHOLE tool call as antml/XML text stuffed into the `answer` string (`...see your GP</answer>\n<answer_disposition>...`), leaving the JSON with only an `answer` key (measured raw rate ~20-40%, rising with answer length). This is PROVIDER-TRANSPORT repair, so it lives in `llm.py` (`repair_compose_output`, passed as the `repair` hook to `call_structured`/`structured` and applied to the raw tool `block.input` BEFORE `ComposeDraft` validates) — **not** in `models.py`, which stays pure declaration. It strips any leaked envelope off `answer`, recovers the `cited_markers`/`answer_disposition` it carried (so evidence chips survive — safe because `_compose_response` drops any marker absent from the analysis), and defaults a still-missing disposition to "answered" (never a field default — that would drop the field from the tool schema's `required` array and worsen the omission). `ComposeDraft.answer` is `min_length=1`, so a leak with no real prose strips to `""`, fails validation → `LLMParseError` → the fallback (never a blank member message). EVERY externally-authored string rendered inside the composer's tag structure — replayed history, the current question, AND the bundle/feedback-sourced profile, notes, active-observation, and preference text — is tag-stripped in the composer render (`llm._strip_structural_tags`, a **fixpoint** `re.sub` — one pass lets a nested tag reform, e.g. `<sa<notes>fety…>` → `<safety…>` — scoped to *our* section-tag names: `profile`/`trajectory_analysis`/`notes`/`safety`/`active_observations`/`member_preferences`/`conversation_history`/`question`) so a hostile bundle or `/feedback` payload can't inject a fake section boundary; only the deterministic `trajectory_analysis` numbers are left un-stripped (core-computed, trusted), and the gate still classifies the RAW message. Composer **rule 8** carries the multi-turn discipline: on a follow-up (when `<conversation_history>` is present) refer to already-given markers by name and answer the delta (risk question → directional meaning; action question → next step) — but **always** state a flagged marker's out-of-range/panic status, even one surfaced in an earlier turn (never trend-only; that would falsely reassure — the *Every narrator surfaces the core flags* invariant). See [[ask-fallback-signature-and-multiturn]].
- **Statistics are classical, not ML** — Mann–Kendall, Theil–Sen, RCV, FDR. Keep the distinction precise; there is no trained model here.
- **Determinism in the core.** Temperature 0 for the gate (Haiku); the composer runs on Sonnet 5, a 5-generation model that rejects sampling params, so it omits temperature and disables thinking instead (keyed on `config.ADAPTIVE_ONLY_MODELS`, the 5-gen capability set co-located with the model pins) — substance-determinism rests on the pure core + the gate's temp 0 + forced-tool structured output, with only composer prose free to vary. The deterministic path must be byte-identical across re-runs.
- **Test the core in isolation** against the known-answer fixtures before wiring anything to it. At n = 3 the honest verdict is "too short to call a trend" — a correct output, not a failure.
- **No browser storage in the UI** — the static page holds state in memory only.
- **Docs are part of the change.** If a change alters what `README.md` or this file documents — a command, the route surface, setup, structure — update them in the same change. A doc that lies about the code is a bug.
- **Keep this file current.** CLAUDE.md does not update itself. After completing a task or plan, ask whether it changed a rule, command, contract, invariant, or structural fact this file describes — if so, edit CLAUDE.md (and `README.md` where relevant) in the same change. Only encode durable operating rules; do not log routine code changes, fixes, or anything already recoverable from the repo or git history.
